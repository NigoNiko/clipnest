# ClipNest 待讨论改进清单

记录日期：2026-10-10  
状态：Version 1.00.3 为当前公开版本。

**界面复核（2026-10-14）**：设置页已收紧窗口和控件间距，让开关紧邻对应文字；链接图标使用白色圆角容器。文件名悬停时完整显示在白底圆角提示框内。Windows 实机界面已重新核对。

**实施顺序（2026-10-13）**：先重组设置页与数据迁移，再处理语言即时切换和设置项；之后统一选中边框、宽屏卡片和链接预览，最后完成首次启动体验、真实窗口核对与构建。此顺序按用户要求先做牵涉面大的结构调整，避免反复改动小功能。

这份清单用于下一轮集中讨论。标为“待定”的内容只是想法，不代表已经决定实施。

**视觉确认规则（2026-10-13）**：所有视觉类改动，以及会引起界面外观变化的功能改动，都先提供改动预览参考给用户查看。用户确认视觉方向后，才考虑代码实现；实现后再核对真实窗口效果。未经确认的预览不作为最终设计。

## 1. 精简偏好设置

**现状感受**：页面仍显得有些乱，不够简洁，常用操作不够高效。

**期望方向**：重新梳理页面层级、分组、文字和操作路径，让常用设置更容易找到和修改，同时保持与主窗口一致的视觉语言。

**待讨论**：哪些设置最常用、哪些可以收进次级页面；先做视觉参考，再确定布局。

**预览反馈（2026-10-13）**：上一版左右分栏的导航方式不喜欢，重新提供无独立导航栏的设置布局参考。保留已认可的字体、加粗标题、快捷键图示及开关样式。布局仍待逐项确认。

**新增参考（2026-10-13）**：用户提供 [Appearance settings — Untitled UI](https://dribbble.com/shots/24366677-Appearance-settings-Untitled-UI) 作为设置页参考。已制作[参考方案 C](previews/设置页-Dribbble参考版.html)，借鉴清楚的页标题、设置行、细分隔线和外观选项缩略图；是否采用顶部轻量标签仍待用户确认。

**方案 C 反馈（2026-10-13）**：整体布局认可。分组改为“常用设置”（外观、语言、透明度）、“个性化”（呼出快捷键、粘贴习惯、开机启动、快捷键说明）、“数据与隐私”（合并原记录与隐私、数据与备份）和“关于”（版本与更新）。

**方案 C 细化（2026-10-13）**：分类标签下方不再重复显示页面标题和说明，直接进入设置项。外观模式缩略图使用简化线稿，保留现有主窗口的收藏夹栏、右侧操作区和横向卡片结构，但不展示真实截图的文字与细节；此前尝试的截图版过于具体，已从参考稿中撤下。更新后的分组和间距仍待视觉复核。

**方案 C 再修订（2026-10-13）**：将“常用设置”改名为“外观”。上一轮的线稿仍把横向主窗口压进方形缩略图，比例失真；参考稿现改为每种模式一条宽而浅的横向窗口轮廓，展示顶栏与整排预览卡片。“窗口透明度”按现有程序的“透明／默认／不透明”三档显示，不用百分比呈现。以上仍待用户视觉确认。

**方案 C 布局纠正（2026-10-13）**：用户澄清原先三个并排的紧凑外观预览布局是正确的，问题只在缩略图内容。撤回占地过大的三条横向布局，恢复三个并排小预览；内部线稿按现有主窗口重绘为左侧收藏夹、右侧操作按钮、下方横排卡片。仍待视觉确认。

**外观模式最终讨论方向（2026-10-13）**：用户认为小缩略图始终无法准确表达 ClipNest 主窗口，决定在设置页参考稿中取消外观预览，改用简洁的下拉框选择“跟随系统／默认／黑暗模式”。此项不再制作缩略图；程序尚未修改。

## 2. 删除“忽略指定应用”功能（方向已定，未实施）

**决定方向（2026-10-13）**：移除“忽略某些 App 的复制内容”的设置与功能，改由现有“暂停记录”控制是否采集。当前只是产品方向，尚未修改程序。

**配套体验**：减少频繁暂停、恢复的操作负担，并使暂停状态足够显眼，避免用户误以为仍在记录或已停止记录。旧设置中已有的忽略列表如何平稳退出，待实施阶段确定。

## 3. 统一选中边框

**期望**：预览卡片与收藏夹的选中框使用一致的颜色和视觉规则。

**待修问题**：两个选中框的圆角看起来不够流畅；边框四周似乎有粗细不一或局部被遮挡的现象。

**实施前检查**：核对边框绘制、圆角半径、抗锯齿、内外边距和图层裁切，确认原因后再调整。需要在浅色、深色及不同缩放比例下看实际窗口效果。

**预览反馈（2026-10-13）**：卡片和收藏夹选中轮廓的线条粗细已认可；最终选中颜色尚未明确选定。

## 4. 安装新版本后的首次亮相

**期望**：新版本安装完成后，第一次启动时自动显示 ClipNest 主窗口，带来“新快递到了”的轻快感。

**待讨论**：首次安装和覆盖升级是否都触发；如果安装器没有选择立即启动，下一次手动启动是否展示；如何保证只出现一次，且不打断正常的开机启动习惯。

**预览选择（2026-10-13）**：选 A，首次亮相时直接展示主窗口，不加额外的欢迎提示卡。首次安装与覆盖升级的触发范围仍待确认。

## 5. 语言切换与英文文案

**期望**：在设置中切换语言后立即更新界面，不要求重启 App。

**英文排版方向**：重要标题和按钮采用一致的英文标题大小写，例如 **Check for Updates**；短介词、冠词等按英文标题规则保留小写。说明文字、帮助提示等小字维持自然的句式大小写，不机械地把每个词首字母大写。

**实施前检查**：主窗口、设置窗口、菜单、弹窗、托盘菜单与运行中状态能否一起刷新；切换语言后控件宽度和文字换行是否正常。统一复核英文文案。

**预览反馈（2026-10-13）**：语言切换后，各按钮应按新文案自适应宽度；同一排的其他按钮也要随之重新排布，避免互相挤压、遮挡或留下不自然的空隙。

## 6. 不同分辨率下的卡片数量与布局（2026-10-12 收集）

**观察**：1080P 显示器上一屏约显示 9 张多一点预览卡片；4K 显示器上一屏显示十几张。希望明确 ClipNest 对不同分辨率、Windows 缩放比例和多显示器的适配策略，再决定是否调整。

**当前实现**：呼出窗口时读取鼠标所在屏幕的可用宽度（排除任务栏等保留区域），窗口近乎铺满该屏幕宽度；卡片宽 188、间距 14，均为固定的 Qt 逻辑像素。内容多时横向滚动，只创建当前视野附近的卡片。没有按屏幕尺寸设定固定的每屏卡片数，也没有在大屏上自动放大卡片。实际张数取决于显示器的**有效逻辑宽度**，因此同是 4K，Windows 设置为 125%、150% 或 200% 缩放时的张数也不同。

**待讨论**：大屏应继续显示更多卡片，还是控制在约 9～10 张并增加单卡尺寸、信息量或两侧留白？还要确认不同显示器之间拖动、呼出时，窗口尺寸和卡片密度是否自然。

**验证时记录**：两台设备分别提供分辨率、Windows 缩放比例、任务栏位置和一屏可见卡片数；检查 1080P、4K、浅色／深色模式下的文字、图标清晰度与卡片选择框边缘。

**预览选择（2026-10-13）**：保留预览所示的显示逻辑：大屏有效逻辑宽度足够时，卡片适度加宽，仍能比小屏显示更多内容；以实际设备效果确定阈值与宽度。

## 7. 链接图标对比度与长标题显示（2026-10-12 收集）

**复现链接**：<https://skills.wheresryan.sh/anatomy>。截图中图标区域看起来是一块空白，标题 “Anatomy · A skill for Claude Code” 被裁切。

**图标事实**：该页面在 2026-10-12 声明 `/anatomy/icon.svg?...`，图形是在透明背景上的白色圆形；根目录的 `/favicon.ico` 与 `/apple-touch-icon.png` 返回 404。当前链接卡片有图标时使用白色底框，白色 SVG 与白底几乎没有对比，因此不能仅凭截图认定图标下载失败。后续先核对图标是否成功解码、缓存，再解决浅色／透明图标与底框的对比度。应采用通用的背景或对比度策略，不为单个网站写例外规则。

**标题事实**：当前标题可换行，但展示区域固定高度只有 24 个逻辑像素；另按前 80 个字符裁切。这样的字符上限无法反映实际字体宽度和行高，标题到第二、第三行时可能直接被区域裁掉，也没有可靠的省略号提示。

**建议方向，待视觉确认**：卡片内标题最多显示两行；超过两行时，按实际字体测量和可用宽度，在第二行末尾加 `…`。不通过持续缩小字号容纳任意长标题，以免不同卡片的文字大小失去一致性。完整标题应仍可通过详情或其他键盘、鼠标均可访问的方式查看；站点名称和来源时间继续占固定位置。中英文、长单词、无空格文本、emoji 和不同 Windows 缩放比例都要验证。

**预览反馈（2026-10-13）**：同意标题两行后显示省略号；图标、标题、网站地址这一组应整体下移，不要靠近卡片顶部。网站地址固定单行，超出可用宽度时显示省略号；完整地址仍可在详情中查看。这两处需要更新视觉参考后再确认具体间距。
